# Sol: Relay browser script review

I inspected `public/app.js` after independent API and worker verification. This is source review; root owns browser automation. I focused on draft preservation, duplicate submits, step order, run polling, and session recovery.

The editor stores changes in `state.edit` as the user types. Save and publish disable editor controls while the request is active. Publishing first saves a dirty draft, then publishes its returned revision; a 409 preserves the local fields and shows a conflict banner with an explicit reload action. Navigation warns before discarding a dirty draft. Run creation uses a stable key while the dialog and input stay unchanged, and disables its controls during submission. Polling uses both page and refresh tokens, so an old run response cannot overwrite a newly selected run. These conclusions follow from the code; they are not browser observations.

I reported two source-level issues to the builder. First, server sessions expire after seven days, but a 401 in the original two-second `refresh()` loop only wrote a page error. Navigation remained in the stale shell, while Logout's DELETE request also required authentication. Second, the wait-duration input handler stored `Number(input.value)`. Clearing the required field made `Number('')` become 0; reordering the step rerendered that blank as a valid zero-millisecond wait. The builder added a session recovery dialog on 401, with an explicit re-login that preserves the draft and does not automatically repeat a write, and made Logout treat an expired session as already signed out. The wait handler now preserves an empty string through rerender, so native required validation blocks save or publish. Source inspection confirms these changes; root owns browser verification.

The step move controls swap entries in the draft array before rerendering, so the stored step definitions move together. Focus restoration currently aims at the moved step's up/down button, which can be disabled at the boundary; root's keyboard browser check can determine whether that needs further adjustment.
